Respite: Detecting Recording-Station Failures in Robot Training Data

Robot training data is recorded at stations: a robot, its cameras and a recorder. When one part of a station degrades, every episode it records can look fine on video while the streams no longer line up. Respite checks recordings for these relationships and points to the station. This release tests whether a trained model does that better than Respite's existing rules, on a recorder it has never seen.

The decision

A trained model is not reliably better than the rules. By the rule fixed before the test run, one of its three training seeds beat the shipped rules and two did worse (details). We recommend not shipping it.

More measurements help more than learning. The robust baseline uses measurements the rules do not read, and caught {{ test.point.robust_z.recall | pct0 }} of faults against {{ test.point.rules.recall | pct0 }}, earlier in {{ test.paired_delay.robust_z_vs_rules.detector_faster | int }} of {{ test.paired_delay.robust_z_vs_rules.n | int }} faults both caught. It raises more alerts on untouched recordings, and it cannot see a station that was broken from its first episode; the rules can. The two belong side by side.

How the test was set up

Two datasets, kept apart

Development: one robotics team's recordings, two stations, {{ data.dev.episodes | int }} episodes. Respite's rules were tuned on it, so it is never used as test data. External test: {{ data.test.episodes | int }} episodes of XDOF ABC-130k (Apache-2.0), another company and another recorder, scored once.

Frozen before scoring

The design, split and fault code were hashed before any training; the models and thresholds were hashed before the test run. Six fault types: camera frames, recorder rate, recorder pauses, command-to-motion delay, camera clock drift, missing streams.

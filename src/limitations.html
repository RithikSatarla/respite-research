Limitations

What this evidence does not show

Read this page before quoting any number from the benchmark.

Synthetic faults, real recordings

Every detection number comes from faults we wrote into real recordings. They test whether a detector notices a specific, known change. They do not show how often real stations fail, which failures matter most, or how a detector does on failures we did not think to simulate. Strong results on synthetic faults are not production accuracy.

No independent labels

None of the datasets here carries independent, human-checked labels of station faults. The development set's training_valid flag is written by that team's own recorder. Respite's earlier findings on these datasets were made by Respite's own checks. The real-data replay on the benchmark page is therefore descriptive: it says where each detector raised alerts, not whether those alerts were right.

The development set shaped the rules

Respite's shipped rules were tuned on the development set, and the model was trained on faults injected into it. Development numbers are reference only. The external test set (XDOF) was not used to tune any threshold, but Respite's MCAP reader and delay estimator were built and checked on it earlier.

Small and narrow

  • The test set has {{ data.test.segments | int }} segments ({{ data.test.episodes | int }} episodes) from one company's recordings. Each fault type is tested on {{ data.test.segments | int }} trials; intervals are wide.
  • Both datasets use bimanual YAM-style arms. Behaviour on other robots, other recorders and other file formats is unknown.
  • The test set has no physical station field. Its "stations" are recording streams that mix operators and days.
  • The XDOF format logs camera message times but not capture times or frame ages, so frozen or repeated camera frames cannot be measured there by any detector here.

Retrospective, not live

All of this ran on stored files in recording order. Nothing here was a live deployment. The operator workflow (alert, acknowledge, record a fix, recheck) exists as software and is tested on synthetic batches; it has not been used by a station operator, so no claim is made about time saved or data recovered.

Software checks are not a safety check

When Respite's checks pass, the recorder, cameras and arms logged in step on the episodes checked. That does not show the station is safe, calibrated, or that the data will train a good policy.

HFlow comparison

HFlow ships measurements without default pass/fail rules for timing, so the comparison applies its documented cohort z-score pattern and its own fps and topic classifications. HFlow needs the video payload, which most of our stored test files do not carry, so it was compared on 30 full-video episodes, episode by episode, not on station sequences. A different configuration of HFlow, written by someone who knows it well, could do better.

No customer results

There are no customer savings, accepted-data rates or production figures on this site because none have been measured.
